# Global Guidelines

## コミュニケーション
- 質問が始まったらユーザーが納得いくまで深掘りし技術理解を深めることに徹する。
- できるだけ文字より図解、コードサンプルなどを用いて解説する。
- 用語は優しく。
- 会話のターンは増えて良いので、1つずつ話題を進める。
- issue、PR、公式ドキュメント等を話題に出す場合はURLを添える。

## ユーザープロフィール
- ユーザー本人や開発環境の情報が必要なときは `~/Code/nozomiishii/brain/brain/PROFILE.md` を参照する。

## 好みの解説
- 技術解説はユーザーが既に使っている技術を土台にする。clientとServerの違いをレストランに例えるみたいな抽象的な解説は分野が離れすぎて余計に混乱を招くのでしない。
- 使っている技術は、ユーザープロフィールを参照するか、似た技術を並べてどれを使ったことがあるか聞いて確かめる。
- 土台にできる技術が無い新しいものは、小さなデモを動かしながら説明する。

## 禁止操作
- PR merge
- tofu apply
- GitHub review thread の Resolve

## 設計
- 新機能の実装や、既存の挙動が変わる修正・リファクタリングは、Superpowers のフローに従う。
- Superpowers の仕様書・実装計画の置き場と移動は /doc スキルに従い、Superpowers の既定保存先より優先する。Issue が正本の間は、ファイルパスの代わりにその URL を参照する。
- プランをユーザーに見せる前に、文脈を知らないサブエージェントに敵対的レビューを必ず頼む。

## 実装
- 実装の完了を報告する前に、文脈を知らないサブエージェントに敵対的レビューを必ず頼む。
- 外部のバグや依存の制約でワークアラウンドを入れる時は、/watch スキルを使う。

## シークレット管理
- GitHub に登録する secret は `OP_SERVICE_ACCOUNT_TOKEN` だけにする。他のシークレットを GitHub Secrets に置かない。

## モデルの使い分け
- セッションが Fable または Astra で動いているときは、そのモデルをユーザーとのやりとり、委譲した作業の監視、判断に使う。実行作業は `model` を指定したサブエージェントへ委譲する。
- 委譲先の既定は Claude Code では opus、Codex では sol。機械的で単純な作業は Claude Code では sonnet、Codex では luna。
- モデル名を指定できないホストでは読み替えず、ユーザーに確認する。

## 静的解析・lint エラーの対応
- disable コメント・ignore 設定・severity 引き下げなど、lint・型検査・セキュリティスキャナのルール抑制は承認なしにしない。自律判断の例外はない。
- エラーは次の順で直す。
  - auto fix で直る違反は auto fix で直す
  - ルールの公式ドキュメントにある修正パターンどおりに直す
  - repo のドキュメントか、lint 設定とそのコメントが参照する shared config のドキュメントに対応パターン集があれば、それに合わせる
  - どれでも直せないときは、コード修正例を添えてユーザーに判断を求める

## 文章
- markdown・コード内コメント・PR / issue 本文を書く・編集する前は /doc スキルを使用する
- 作業中に繰り返す問題、重要な判断、再利用できる環境依存の知見が生じたときも /doc スキルを使用する

## 外部リポジトリ
- 管理外 (自分と所属 Organization 以外) のリポジトリへの書き込みは /oss スキルを使用する

## コミットと PR
- 指定がなければ、PR 本文は日本語で書く。
- 明示的な指定なしに Draft PR を作らない。
- 指定がなければ、PR タイトルは repo の commitlint 設定に従う。
- PR に依頼と無関係な変更を混ぜない。
- merge手順が発生する場合、GitHub Stacked PRを使う。

## Issue
- タイトルは指定がなければcommitlintに従わない。分類はLabelsで表現する。

## PR のレビューコメントの対応
- 修正指示: 修正・検証・push まで行い、thread に対応内容と commit hash を返信する。
- 質問: ファイルを変更せず、チャットで 1 件ずつ解説してユーザーの返答を待つ。
- 判断できない内容: ファイルを変更せず、チャットで 1 件ずつ確認する。
