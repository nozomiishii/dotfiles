# 操作リファレンス

## 前提

- macOS 13以上、Python 3.10以上、OBS 28以上が必要。
- 開始前に `doctor` の `screen_locked` が `false` であることを確認する。ロック中なら本人に解除を頼み、解除後に再確認する。
- OBSのWebSocketサーバーは認証を有効にする。補助処理の接続先は同じMacに限定する。これはOBSサーバーの待受を同じMacだけに制限する設定ではないため、受信制御を確認し、有効化で増える接続範囲を本人へ伝える。
- 録画は標準ファイル出力を使い、分割録画と既存ファイルの上書きはオフにする。Simpleモードでは品質を `HQ` または `Small` にする。FLV・Lossless・Custom FFmpegは使わない。
- 初回設定は利用できるアプリ・ブラウザ操作で行う。操作用サーバー有効化と、Macの画面・音声・マイクの新しい許可は、必要な変更をまとめて提示し、実行直前に本人へ確認する。

## 初回のOBS設定

既存のシーンと入力を残し、次を追加する。

| 対象   | 名前              | 設定                                                                     |
| ------ | ----------------- | ------------------------------------------------------------------------ |
| シーン | `Meet recording`  | このスキル用                                                             |
| 画面   | `Meet screen`     | macOS Screen Capture。ウィンドウ単位で音声も取り込む。ミュートを解除する |
| マイク | `Meet microphone` | Audio Input Capture。Meetで使うマイクを指定する                          |

- 画面収録・システム音声・マイクのMac側の許可を確認する。
- OBSのWebSocket設定を認証付きで有効にする。パスワードは表示・転記せず、既存のローカル設定から補助処理が読む。
- 録画先は本人が指定した場所を使う。未指定なら `~/Movies/Meet` を提案する。
- 画面の文字と双方の音声が入ることを短い試し録画で確認する。

詳細は[OBSのリモート操作](https://obsproject.com/kb/remote-control-guide)、[Macの画面・音声取り込み](https://obsproject.com/kb/macos-desktop-audio-capture-guide)、[Macの権限](https://obsproject.com/kb/macos-permissions-guide)を参照する。

## 補助処理

`python3 "$HOME/.agents/skills/meet-recording/scripts/record.py" --help` で利用できる操作を確認する。

| 操作             | 引数                           | 結果                                             |
| ---------------- | ------------------------------ | ------------------------------------------------ |
| ローカル設定確認 | `doctor`                       | 設定の有無と接続の準備状態。接続しない           |
| Meet候補         | `targets`                      | OBSが取得できるMeetウィンドウの候補              |
| 開始             | `start --target-id <候補のID>` | 対象と音声設定を確認して開始状態を返す           |
| 状態             | `status`                       | 録画状態と、このスキルが開始した録画かを返す     |
| 停止             | `stop`                         | このスキルの録画を停止し、保存ファイルを確認する |

汎用の上流CLIは直接呼ばず、録画用の補助処理を使う。出力にはパスワードや生の通信ログを含めない。

## 開始依頼

- ブラウザ操作で本人が参加する `meet.google.com` のタブを確認する。複数ある場合は対象を聞く。
- Meetは専用ウィンドウで開く。録画中に別タブへ切り替えると、同じウィンドウに表示された内容が録画される。
- `doctor` の結果を確認する。
- `targets` の結果とブラウザのMeetが同じ会議であることを照合する。
- 候補がない場合は、実際にOBSから選べる画面・権限を確認する。
- 選んだ候補のIDを使って開始する。
- 補助処理が開始を確認できたら、録画中であることと「止めて」で停止できることを短く伝える。
- 既に録画中なら開始を重ねない。このスキルが開始した録画か、別用途の録画かを結果から伝える。

## 停止依頼

- `stop` を使う。所有を確認できない録画は、OBSの停止ボタンで代わりに止めない。
- 保存を確認できたときだけ、絶対パスのファイルリンクを返す。
- 停止や保存を確認できない場合は、現在の状態と未確認の点を伝える。`status` で再確認する。
- 元の録画は削除・変換・上書きしない。
- 開始後の保存パスと録画時間で対象を照合する。OBSを手動で停止・再開始した場合は停止を依頼する前に状態を確認する。照合と停止を不可分に行うAPIはないため、その間の手動操作は避ける。
