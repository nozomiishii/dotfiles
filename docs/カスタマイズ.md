# カスタマイズ

dotfiles を書き足すときに使う調べ方。

## 外部スキルを追加・更新する

- 既存の Mac では dotfiles 本体で一度 `mise exec -- pnpm install --frozen-lockfile` を実行して Git フックを入れ、`mise run skills` で現在のロックを反映する。新規セットアップでは `install.sh` が両方実行する。
- 追加するときは dotfiles のルートで `mise -C external-skills exec -- skills add https://github.com/<owner>/<repo>/tree/main --skill <name> --agent codex --yes` を実行する。スキル本体は Git が無視する `external-skills/.agents/skills/` に入る。[skills CLI の使い方](https://github.com/vercel-labs/skills/blob/main/docs/commands.md)
- 手元の Codex、Claude Code、Cursor で使えるように、追加時に一度だけ `ln -s ../../../external-skills/.agents/skills/<name> home/.agents/skills/` でリンクを作り、`external-skills/skills-lock.json` と一緒にコミットする。スキルを外すときはリンクも削除する。
- 毎週月曜に GitHub Actions が `skills update --project --yes` で上流の `main` を確認し、ロックが変われば更新 PR を作る。dotfiles 本体に取り込むと、Git の post-merge フックがそのコミットを復元する。[更新ワークフロー](../.github/workflows/update-skills.yaml)
- 更新 PR のレビューでは、`skills-lock.json` の更新前後のコミットを上流で比較する。[yomiyasu の変更履歴](https://github.com/nanaism/yomiyasu/commits/main/skills/yomiyasu/)
- 手元のコミットをリベースして更新を取り込んだ場合は、dotfiles 本体で `mise run skills` を実行する。

## macOS の defaults

### 設定を変えて書き換わるキーを探す

```shell
defaults read > before
# change the config
defaults read > after
diff before after
```

### アプリの plist を探す

```shell
  ll ~/Library/Preferences/ | grep <app_name>
  # example
  ll ~/Library/Preferences/ | grep firefox
```

### アプリの設定を読む

```shell
  defaults read <app_name_plist>
  # example
  defaults read notion.id
```

### NSGlobalDomain の plist を開く

```shell
open ~/Library/Preferences/.GlobalPreferences.plist
```

## シンボリックリンクを張る

```shell
  ln -nfs <New_linking_file> <Existing_linked_files>
  # example
  ln -nfs "$HOME/Google Drive/Settings/dotfiles/zshrc" "$HOME/.zshrc"
```

## zsh の起動時間を測る

```shell
for x in {1..10}; do time zsh -i -c exit; done
```
