# カスタマイズ

dotfiles を書き足すときに使う調べ方。

## Brewfile にアプリを追加する

一部の cask は [mise で管理する](<decisions/brooklyn は Brewfile ではなく mise bootstrap.packages で管理する.md>)。

```shell
  brew search <app_name>
```

```shell
  brew info <app_name>
```

## macOS の defaults

### 設定を変えて書き換わるキーを探す

```shell
defaults read > before
# change the config
defaults read > after
diff before after
```

### アプリの plist を探す

```shell
  ll ~/Library/Preferences/ | grep <app_name>
  # example
  ll ~/Library/Preferences/ | grep firefox
```

### アプリの設定を読む

```shell
  defaults read <app_name_plist>
  # example
  defaults read notion.id
```

### NSGlobalDomain の plist を開く

```shell
open ~/Library/Preferences/.GlobalPreferences.plist
```

## シンボリックリンクを張る

```shell
  ln -nfs <New_linking_file> <Existing_linked_files>
  # example
  ln -nfs "$HOME/Google Drive/Settings/dotfiles/zshrc" "$HOME/.zshrc"
```

## zsh の起動時間を測る

```shell
for x in {1..10}; do time zsh -i -c exit; done
```

## 外部スキルの版を上げる

yomiyasu はリポジトリに同梱しない。版は `home/skills-lock.json` の `ref` で固定し、セットアップ時に skills CLI が `home/.agents/skills/yomiyasu/` へ入れる。

```text
Renovate が ref を上げる
        |
        v
CI の frozen install が失敗する
        |
        v
skills add で computedHash を作り直す
        |
        v
上流の compare で中身を確認する
```

- Renovate が `ref` だけを上げた PR は、`computedHash` が古いままなので CI が失敗する。
- checkout の `home/` で次を実行し、hash を作り直す。`vX.Y.Z` は PR の新しいタグにする。CLI の版は `mise.toml` の `npm:skills` に従う。

```shell
cd home
mise exec -- skills add nanaism/yomiyasu@vX.Y.Z --skill yomiyasu -a claude-code -a codex -a cursor -y
```

- 入った中身は `https://github.com/nanaism/yomiyasu/compare/<今のタグ>...<新しいタグ>` で確認する。
- このリポジトリでは `npx skills` を使わない。`package.json` が package manager を pnpm に固定していて、npm が実行を止める。`mise exec` の `skills` を使う。
- `npm:skills` を 1.8.1 より上げるときも、同じコマンドで lock を作り直す。v1.8.1 の時点で、skills CLI の main には lock へ commit を書き、復元はその commit を使う未リリースの変更がある。hash と commit の両方を、上げた CLI で書き直す。[^skills-cli-commit]
