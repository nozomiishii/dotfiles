# 開発フローは dev スキルを正本にする

## 背景と課題

機能開発でプランの省略、プランの考慮漏れ、実装後の手戻りが繰り返し起きていた。AGENTS.md の「新機能や修正の前に plan mode で計画」ルールは常時コンテキストにあっても発動が担保されず、指示の言い換えでは解決しない状態だった。

## 検討した選択肢

### 発動の担保

| 選択肢 | 評価 |
| --- | --- |
| 自動発動スキル | Claude Code と Codex の両方で同じ挙動。発動判定はモデル任せ |
| PreToolUse hook 併用 | 取りこぼしを機械的に防げる。承認状態の管理と検証が増える |
| 明示起動のみ | 誤発動ゼロ。打ち忘れのリスクがユーザー側に移る |

### 敵対的レビュアー

| 選択肢 | 評価 |
| --- | --- |
| サブエージェント | 速く安く、Claude Code と Codex のサブエージェント機構で同等にできる。同系モデルの盲点は共有される |
| 別モデルの相互レビュー | 盲点が重ならず検出力は最大。相手側 CLI の導入・認証が前提で遅い |

### プランの置き場

| 選択肢 | 評価 |
| --- | --- |
| issue のみ | doc スキルの「着手したら docs/ へ移す (正本は 1 つ)」と衝突し、正本が分裂する |
| issue に起こし着手時に docs/ へ移す | doc スキル準拠。承認の証跡が issue に残る。移す手間が毎回かかる |
| docs/ 直行 | 手間は最小。承認の証跡が issue に残らない |

### AGENTS.md「設計」セクションの扱い

| 選択肢 | 評価 |
| --- | --- |
| 削除して dev スキルに一本化 | 記述は 1 箇所になるが、スキルが発動しなかったとき常時コンテキストに何も残らない |
| 1 行ポインタとして残す | 不発動時の防波堤になる。行数の負担はほぼ無い |

## 決定

- 自動発動スキル dev を開発フローの正本にする。hook は今回入れない
- 敵対的レビューはプラン確定時と実装完了時にサブエージェントへ依頼する
- プランはユーザー承認時に対象 repo の issue へ起こし、着手時に docs/ へ移す
- AGENTS.md の「設計」セクションは削除せず、dev スキルへの 1 行ポインタとして残す。スキルが発動しなかったときの防波堤にする
- フローの不発動や手戻りの検知は retro の汎用の振り返りに任せ、retro / fb への観点追加はしない

## 結果

### 良くなったこと

- プラン・敵対的レビュー・ユーザー判断の各ゲートが、記憶頼みでなくスキルの手順として発動する
- Claude Code と Codex で同じフロー定義を共有できる

### 引き受けたコスト

- 発動判定がモデル任せのため、取りこぼしはゼロにならない
- プラン確定時と実装完了時のレビューぶんのサブエージェント実行コスト

### 保留した論点

- PreToolUse hook の追加。retro でフローの不発動や手戻りが観測され続けたら、hook 併用へ再設計する
