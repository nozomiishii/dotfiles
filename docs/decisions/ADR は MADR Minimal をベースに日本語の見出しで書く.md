# ADR は MADR Minimal をベースに日本語の見出しで書く

## 背景と課題

「なぜそう設計したか」を残すために ADR を入れる。書式で変わるのは、読み返したときの情報量、書きやすさ、外部ツールとの相性。

決めるのは 2 つ。ベースにするテンプレートと、見出しの書き方。

## 検討した選択肢

### ベースにするテンプレート

| 選択肢 | 評価 |
| --- | --- |
| Michael Nygard 原典 (2011) | `Status` / `Context` / `Decision` / `Consequences` の 4 セクション。`adr-tools` のデフォルトで最小構成。却下案は `Context` に混ざる |
| MADR Full | 7 セクション。`Decision Drivers` や `Pros and Cons of the Options` まで書く。今は要らない |
| MADR Minimal | `Context and Problem Statement` / `Considered Options` / `Decision Outcome` / `Consequences` の 4 セクション + frontmatter。却下案が独立したセクションに収まる |

### 見出しの書き方

| 選択肢 | 評価 |
| --- | --- |
| 英語のまま使う | MADR を読む外部ツールが解釈できる。本文が日本語なので見出しだけ言語が切り替わる |
| 日本語に置き換える | 見出しを読んだだけで中身が分かる。外部ツールとの互換性は失う |

## 決定

MADR Minimal をベースにし、見出しは日本語にする。

セクションは `背景と課題` / `検討した選択肢` / `決定` / `結果`。MADR Minimal の 4 セクションに順に対応する。

frontmatter は `status` と `date`。本文は日本語で、コードと技術用語は英語のまま書く。

`結果` は `Good, because` の箇条書きをやめ、`良くなったこと` / `引き受けたコスト` / `保留した論点` の 3 つの小見出しに分ける。該当が無いときも見出しを残して `なし` と書く。コストや保留が無いことも判断の記録になる。

`検討した選択肢` は、論点が 1 つなら箇条書きにする。複数あるときは論点ごとの小見出しに分け、それぞれ「選択肢 / 評価」の 2 列表にする。

`決定` が長くなるときは、論点に対応する小見出しで分ける。

## 結果

### 良くなったこと

- 却下案が独立したセクションに残り、後から「なぜこれを選んだか」を追える
- frontmatter の `status` と `date` を機械が読める
- 見出しから中身が分かり、拾い読みで目的の論点にたどり着ける

### 引き受けたコスト

- MADR を読む外部ツールは使えなくなる。この repo に MADR パーサーは無い
- 却下案のセクションと frontmatter があるぶん、Nygard 原典より書き始めが重い

### 保留した論点

- MADR Full のセクションを足せば広げられる。足すときに日本語名を決める
